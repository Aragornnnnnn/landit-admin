# Landit 어드민 — 화면 설계 (공통 스펙)

Figma `🛠 어드민` 페이지의 "00 개요"·"01 템플릿(셸)"·"스펙 — 공통 규칙"을 옮긴 문서다. 화면별 스펙은 [screens/](screens/)에 있다. **Figma와 이 문서가 다르면 Figma가 맞고, 이 문서를 고친다.**

- Figma: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=1050-1576
- 기준 스웨거: 2026-08-18 `api-develop.landit.im` `/api/v1/admin/*` (NPS는 서비스에서 빠져 제외)

## 개요

운영자가 서비스 데이터를 보고 관리하는 내부 도구. 사용자 웹(landit.im)과 완전히 분리해 별도 레포 landit-admin, 별도 도메인 admin.landit.im으로 운영한다. 인증은 사용자 웹과 같은 카카오·구글 소셜 로그인을 재사용하고, 관리자 여부(role=ADMIN)는 백엔드가 판단한다.

Figma는 화면마다 페이지(탭)를 나눴다 — 각 페이지 왼쪽이 화면(데스크톱·모바일·상태 변형), 오른쪽 "스펙 —" 섹션이 그 화면의 데이터·인터랙션·상태·검증·BE 확인 사항이다.

## BE에 아직 없는 것

- 내가 관리자인지 확인하는 API(`/auth/me` 류) — 로그인 가드에 필요
- 사용자 검색(이메일·닉네임)·상태 변경(BANNED)·세션 기록
- 시나리오·표현 콘텐츠 CRUD
- 푸시 발송, 대시보드 집계(가입·DAU·완료율)
- 스웨거 버그: `AdminUserListResponse`의 `items`가 같은 이름 `Item`을 참조해 피드백 형태로 잘못 표시됨

## 셸

- 사이드바 280 — 로고(앱 아이콘 32 + 워드마크 + "어드민") → 서버 카드(예: "개발 서버" / `api-develop.landit.im`, `NEXT_PUBLIC_API_HOST` 또는 `API_BASE_URL`의 호스트) → 내비 → (spacer) → 내 계정
- **열린 질문 — 서버 카드의 `›`**: 스펙 텍스트에는 `api-develop.landit.im ›`처럼 화살표가 있지만 화면 프레임(1050:7054)에는 없다. 누를 곳이 아닌데 화살표만 있으면 되지도 않는 걸 될 것처럼 보이게 하므로 지금은 뺐다. 아래 "가이드·스웨거"를 여기서 열 생각이었다면 그때 링크와 함께 되살린다
- **열린 질문 — 가이드·스웨거**: 아래 규칙에는 있는데 화면 프레임의 내비에는 없다. 어디에 둘지(내비 항목 / 서버 카드 클릭 / 내 계정 드롭다운) 정해야 한다
- 내비 그룹과 순서: **대시보드** / [편지함] **피드백**·**공지·업데이트** / [사용자] **사용자** / [설정] **앱 버전**·**시나리오 테스트**. 그룹 라벨은 13px 회색(#8b95a1), 항목은 15px, 선택 항목 배경 #f2f4f6 r12. 피드백 배지 = 처리중 건수(오렌지 알약, 0이면 숨김)
- 가이드 = 노션 운영 가이드 링크(없으면 제거), 스웨거 = 현재 서버 `/swagger-ui`
- 내 계정(아바타 32 + 이름 13px + "ADMIN · 로그아웃" 11px) 클릭 → 드롭다운(로그아웃). 상단바(높이 88, 좌우 48)는 페이지 제목(28 Bold)만, 액션은 콘텐츠 첫 줄
- 페이지 배경 #F9FAFB, 사이드바 흰색 + 오른쪽 헤어라인 #eef0f3

## 인증·권한

- 사용자 웹과 같은 카카오·구글 웹 단독 소셜 로그인 (`POST /auth/social-login`). 요청은 같은 오리진 프록시로 보낸다(CORS 없음) — 이 레포는 rewrites 대신 route handler 프록시를 쓴다([auth.md](auth.md))
- 관리자 판정 API가 없음 → 임시로 첫 admin 호출 403이면 "관리자 아님" 화면. BE 요청 중(차단 항목)
- 401 → 토큰 갱신 1회 → 실패 시 `/login`. 403 → 관리자 아님

## 반응형

| 폭       | 규칙                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| ≥ 1024   | 고정 사이드바 + 콘텐츠(좌우 48). 테이블                                                                                              |
| 768–1023 | 사이드바 아이콘만(접힘) 또는 드로어. 테이블 가로 스크롤                                                                              |
| < 768    | 햄버거 → 드로어(Sheet). 목록은 카드, 모달은 바텀시트, 선택 액션은 하단 고정 바, 폼은 한 컬럼. 터치 타깃 44px, 하단 바는 safe-area 위 |
| 전환     | 같은 데이터 컴포넌트가 breakpoint로 테이블/카드만 바꾼다(라우트 분기 없음). 폭 변경 시 레이아웃 애니메이션 없음(즉시)                |

- 편집·폼: 한 컬럼 세로 스택, 넓으면 2단(편집 | 미리보기)
- 일괄 답장: 데스크톱 Dialog(640) / 모바일 바텀시트
- 선택 액션: 데스크톱은 테이블 위 바, 모바일은 하단 고정 바

| 상태    | 규칙                                                                                                                                                     |

| 로딩    | 목록 Skeleton 5행 · 카드 Skeleton 블록. 200ms 안에 오면 스켈레톤 생략(깜빡임 방지). 필터 변경은 이전 결과 유지 + 진행바                                  |
| 빈 상태 | 래디 + 한 줄 이유 + 다음 행동 버튼. 필터 때문인지 원래 없는지 문구로 구분                                                                                |

| 결과    | 토스트 = 사용자 웹 확정 알약(성공 초록 ✓ / 오류 빨강 ! / 기본 아이콘 없음)                                                                               |
| URL     | 목록 필터·페이지·열린 상세는 쿼리스트링(`?type=&status=&page=&open=`) — 새로고침·공유·뒤로가기 유지                                                      |

## 톤

앱인토스 콘솔 — 페이지 #F9FAFB, 흰 사이드바 280 + 헤어라인, 테두리 없는 흰 카드(r20), 회색 채움 입력, 단색 아이콘, 제목 28. 색은 회색·검정 + 오렌지(주 행동·선택·처리중 점)만, 빨강은 파괴적 행동·오류에만. 유형·상태 칩은 전부 중립 회색. 장식(아바타·일러스트·설명 문장)은 넣지 않는다.

## 구현 메모

- shadcn/ui: Sidebar(sidebar-07) · Sheet · Dialog/AlertDialog · Select · Popover · DropdownMenu · Table · Skeleton · Toast(sonner) · Tabs · Switch · Checkbox
- 위 "공통 상태"·"칩"은 화면마다 다시 만들지 않는다 — `shared/ui`의 `StatusChip`(중립 칩 + 점) · `EmptyState`(한 줄 이유 + 다음 행동) · `InlineError`(문구 + 다시 시도) · `ListSkeleton`(기본 5행)과 `shared/lib/useDelayedPending`(200ms 규칙)을 쓴다. 어떤 라벨에 어떤 점을 쓸지 같은 도메인 판단은 화면이 하고, 프리미티브는 그걸 모른다
- 데이터: TanStack Query, 목록은 keepPreviousData, 변경 후 관련 쿼리 invalidate(피드백 목록·배지 카운트·대시보드)
- 폰트: 사용자 웹과 동일. 색: apps/web globals.css 토큰을 어드민 CSS 변수로 복사(페이지 배경만 #F9FAFB)

## 목록 행 다듬기 (운영자 결정 · 2026-08-24)

Figma 프레임과 다르게 확정한 것들 — 앱인토스 콘솔 목록을 레퍼런스로 운영자가 결정했다. Figma를 이 규칙에 맞게 갱신해야 한다.

- 데스크톱 표의 행 오른쪽 화살표(›)를 그리지 않는다. 행 전체가 hover로 반응하므로 클릭 어포던스는 전달된다. (모바일 카드의 ›는 유지)
- hover 행은 카드 가장자리에 겹칠락 말락하게 붙인다 — 카드 안쪽 여백 4px(px-1), 행 모서리 8px(rounded-lg).
- 행 hover는 어느 행에서나 같은 색 --hairline(#EEF0F3).
- 줄무늬(한 줄 걸러 옅은 배경 #F4F5F7)는 깔지 않는다 — 행 배경은 흰색 하나, 행 구분은 hover만 (2026-08-25 결정, 프레임의 줄무늬는 실사용에서 복잡해 보였다).

## 셸 다듬기 (운영자 결정 · 2026-08-25)

- 사이드바 서버 카드(두 줄: "개발 서버" / 호스트)는 한 줄로 줄인다 — 점 + "개발 서버 · {호스트}"(12px). 카드처럼 크면 눌러야 할 것처럼 보인다는 피드백. Figma 갱신 필요.
- 서버 표시가 환경을 가른다(2026-08-26 점 색 → 2026-08-28 강조 확대) — 개발은 조용한 초록 점 + 회색 글자, **운영은 오렌지 칩(배경칠 + 흰 글자)로 도드라지게**. 실사용자에게 영향 가는 환경임이 한눈에 박혀야 한다. 사이드바와 모바일 상단바(ServerBadge) 동일 규칙.
