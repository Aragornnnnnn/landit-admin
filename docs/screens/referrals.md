# LAN-696 레퍼럴 관리.

기준은 LAN-696 승인 설계다. 별도 Figma 프레임 없이 기존 어드민 셸·카드·폼·확인 대화상자를 사용한다.

- `/referrals`에서 가입 완료와 첫 실제 결제 보상의 활성화, 대상, 초대인·피초대인 금액을 독립 편집한다.
- 금액은 수령자별 1~1,000,000원 정수다. 비활성/비대상 금액은 0으로 보낸다.
- 결제 대상 상품은 RevenueCat 앱·스토어·상품 ID·구독/일회성 유형을 입력한다. 결제 보상 활성화 시 하나 이상 필요하다.
- 변경 사유를 입력하고 변경 전후를 확인한 뒤 저장한다. 가입 시 두 단계 혜택이 고정되며 새 정책은 이후 가입자부터 적용된다.
- 동시 수정(409)은 덮어쓰지 않는다. 초안을 유지하고 최신 정책 다시 불러오기를 제공한다.
- 지급 보류/재개는 별도 사유와 확인을 거친다. 과거 약정 금액을 수정하지 않는다.
- 정책 이력, 지급 내역, 결제 수신 내역을 커서 페이지로 조회한다. 지급·수신 재처리는 사유와 확인을 거치며 임의 지급 기능이 아니다.
- 적립은 실제 송금 완료가 아니다. 검토 사유를 보여주고 과거 금액을 다시 계산하지 않는다.
- 모바일은 한 열 카드, 데스크톱은 두 단계 나란히 배치한다. 표는 가로 스크롤 영역으로 제한한다.

검증: 단계 대상/금액 변환, 잘못된 금액·상품, 저장 확인·충돌 유지·보류/재처리 흐름을 네트워크 경계 기반 테스트로 확인한다.

## 검증 결과.

- 생성 API 타입은 `API_DOCS_URL=... node scripts/generate-referral-api-types.mjs`로 갱신한다. 동일 BE 브랜치의 OpenAPI를 사용하며 기존 다른 기능의 스키마를 바꾸지 않는다.
- 전체 519개 테스트 통과 후 revision 고정 회귀 테스트를 추가했고, 레퍼럴 11개 테스트를 재검증했다. TypeScript·ESLint·Next 프로덕션 빌드를 통과했다.
- 백그라운드 조회에서 revision이 바뀌어도 편집 기준 버전을 고정한다. 조회 실패 시 초안을 유지한다.
- 대상 상품은 BE와 같은 최대 50개이며, 사용자 안내용 상품 이름을 필수로 입력한다.
- 로컬 모의 데이터로 1440px·390px 화면, 지급 대상 변경, 저장 확인 전후 금액과 사유를 확인했다. 첨부 이미지는 이 로컬 검증 상태다. 별도 레퍼럴 Figma 원본 프레임은 제공되지 않았다.
