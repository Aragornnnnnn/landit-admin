# 공지·업데이트 (편지)

Figma — 화면: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=1050-10109 · 스펙: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=1050-11266
라우트: /letters · /letters/new · /letters/[id]
API: GET admin/mailbox/letters · POST admin/mailbox/letters · PATCH admin/mailbox/letters/{id} · POST admin/content-images/presigned-url

## 화면 구성

### 목록 (/letters — `1050:10110`)

- 좌측 공통 사이드바(내비 "공지·업데이트" 활성). 상단바 제목 "공지·업데이트".
- 상단 컨트롤 행
  - 탭: `전체` · `임시저장` · `발행됨` · `숨김`
  - 타입 Select: `타입: 전체` (⌄) — 옵션은 스펙상 공지/업데이트/답장
  - 우측 주황 버튼: `새 편지 쓰기`
- 그룹 카드들 (탭 "전체" 기준 3개 카드가 세로로 쌓임)
  - 카드 `지금 편지함에 보이는 편지` (건수 4)
  - 카드 `임시저장` (건수 2)
  - 카드 `숨김` (건수 1)
- 각 카드는 같은 테이블 구조. 헤더 컬럼: `타입` · `제목` · `상태` · `발행일` · `수정` · (빈 헤더 — 행 액션 컬럼)
  - 타입 셀: 칩 `공지` / `업데이트`
  - 제목 셀: (고정이면 앞에 칩 `고정`) + 제목 텍스트
  - 상태 셀: 점 + 칩 `발행됨` / `임시저장` / `숨김`
  - 발행일 셀: `MM.DD HH:mm`, 임시저장은 `–`
  - 수정 셀: `MM.DD HH:mm`
  - 마지막 셀: 더보기 버튼 `⋯`
- 예시 데이터 (화면 프레임 그대로)

### 행 ⋯ 메뉴 (`1050:10602`)

- 발행됨 행에서 열린 드롭다운 항목: `미리보기` · `고정 해제` · (구분선) · `숨기기`
- 프레임 주석 원문: "발행됨 행: 미리보기 · 고정 해제 · 숨기기 / 임시저장 행: 미리보기 · 발행하기 / 숨김 행: 미리보기 · 다시 보이기. 숨기기·발행은 확인 창 → PATCH publicationStatus"

### 숨기기 확인 다이얼로그 (`1050:10862`)

- 제목: `편지를 숨길까요?`
- 본문: `사용자 편지함에서 바로 사라져요. 언제든 다시 보이게 할 수 있어요.`
- 버튼: `취소` · `숨기기` (Destructive)

### 새 편지 / 편집 (/letters/new · /letters/[id] — `1050:10361`)

- 상단바 제목: `공지·업데이트 / 새 편지` (편집 시에는 `공지·업데이트 / {제목}`, 예: "공지·업데이트 / 랜딧 서비스 점검 안내")
- 에디터 상단 액션바 (한 줄)
  - `← 목록`
  - 상태 칩 `임시저장`
  - `마지막 저장 14:20`
  - (spacer)
  - 버튼 `임시저장` (회색) · 버튼 `발행하기` (주황)
- 2단 레이아웃: 왼쪽 "편집" 컬럼(가변 폭) + 오른쪽 "미리보기" 컬럼(고정 340px)
- 왼쪽 편집 컬럼 — 카드 `기본 정보`
  - `타입` — 세그먼트 탭 `공지` / `업데이트`
  - `고정` — 토글 스위치 + 라벨 `리스트 상단 고정`
  - `제목` — 텍스트 입력 (예시값: "1.4.3 업데이트 — 마이크 오류 수정")
  - `미리보기 문구 (목록 한 줄)` — 텍스트 입력 (예시값: "녹음이 안 되던 문제를 고쳤어요. 업데이트하고 다시 시도해 주세요")
- 왼쪽 편집 컬럼 — 카드 `본문 블록`
  - 카드 헤더: `본문 블록` + 우측 안내 `contentBlocks 그대로 저장돼요`
  - 블록 공통 헤더: 드래그 핸들 `⋮⋮` + 타입 칩 + 우측 액션 `↑  ↓  삭제`
  - 블록 종류 3가지 (칩 텍스트 그대로)
    - `PARAGRAPH` — 여러 줄 텍스트 (예시: "안녕하세요, 랜딧 팀이에요." / "일부 기기에서 마이크 권한을 허용해도 녹음이 시작되지 않던 문제를 고쳤어요.")
    - `IMAGE` — 썸네일(96×64) + 파일명·용량(예시: "mic-fix.png · 240KB") + `캡션: 설정 > 마이크 권한`
    - `ORDERED_LIST` — 번호 항목 (예시: "1. 앱스토어에서 1.4.3으로 업데이트해요" / "2. 앱을 완전히 종료했다가 다시 열어요" / "3. 그래도 안 되면 편지함에서 알려주세요")
  - 블록 추가 버튼 행: `+ 문단` · `+ 이미지` · `+ 번호 목록`
- 오른쪽 미리보기 컬럼
  - 라벨 `사용자 편지함 미리보기`
  - 폰 목업(300×560, 라운드 28) 안에 사용자 웹 편지 상세를 렌더
    - 상단 `‹ 편지함`
    - 타입 칩(예: `업데이트`) + 날짜(예: `8월 18일`)
    - 제목
    - 블록 순서대로: 문단 텍스트 → 이미지(268×140) + 캡션 → 번호 목록

### 발행된 편지 편집 (`1050:11122`)

- 새 편지와 동일한 2단 폼. 다른 점은 상단 액션바.
  - 상태 칩 `발행됨` (점 포함)
  - 안내 문구 `발행 8.18 09:00 · 저장하면 바로 반영돼요`
  - 버튼 `저장` (변경 없으면 비활성) · 버튼 `숨기기`
- 프레임 주석 원문: "발행된 편지: [저장 · 숨기기]. 숨긴 편지: [저장 · 다시 보이기]. 임시저장: [임시저장 · 발행하기]"

### 모바일 목록 (`1050:10503`)

- 상단바: 햄버거 메뉴 + 우측 서버 표시(점 + `개발 서버`)
- 타이틀 영역: `공지·업데이트` + 부제 `발행됨 4 · 임시저장 2` + 우측 주황 버튼 `새 편지`
- 세그먼트 탭(꽉 채움): `전체` · `임시저장` · `발행됨` · `숨김`
- 그룹 카드 (라운드 18 흰 카드, 행 사이 구분선)
  - 그룹 헤더: `지금 편지함에 보이는 편지` `4 · 고정 1` / `임시저장` `2` / `숨김` `1`
  - 행 구성: 1행 = 타입 칩(`공지`/`업데이트`) + (고정이면 칩 `고정`) + 우측 날짜(`8.18` 형식) / 2행 = 제목 / 우측 끝 `›`
- 타입 Select와 테이블 컬럼(상태·발행일·수정·⋯)은 모바일 프레임에 없음.

### 화면 프레임 주석에서 보강되는 규칙

- 행 ⋯ 메뉴 항목은 행 상태별로 다르다. 발행됨 행: 미리보기 · 고정 해제 · 숨기기 / 임시저장 행: 미리보기 · 발행하기 / 숨김 행: 미리보기 · 다시 보이기. 숨기기·발행은 확인 창 → PATCH publicationStatus.
- 에디터 상단 버튼 조합은 상태별로 다르다. 발행된 편지: [저장 · 숨기기]. 숨긴 편지: [저장 · 다시 보이기]. 임시저장: [임시저장 · 발행하기].
- 발행된 편지 편집 화면의 `저장` 버튼은 변경이 없으면 비활성으로 그려져 있다(`1050:11122`).

## 검증

스펙에 별도 "검증" 그룹은 없다. 인터랙션·상태 표에 흩어진 검증 규칙만 모으면 다음과 같다.

- 미리보기 문구(preview) 60자 제한. 넘으면 카운터 빨강.
- 발행하기는 제목·본문이 비면 비활성.
- 새 편지는 첫 저장 전 발행 비활성.
- 고정(pinned)은 공지(NOTICE)만 가능. 업데이트는 토글 비활성 + off, 툴팁 "공지만 고정할 수 있어요".
- contentBlocks는 PARAGRAPH · IMAGE · ORDERED_LIST 세 종류만 만든다.

## BE 확인 사항 / 열린 질문

스펙 "BE 확인" 그룹 원문.

- title·preview 길이 제한 값
- presigned-url의 허용 contentType·최대 fileSize

스펙 텍스트와 화면 프레임 사이 차이 등 열린 질문.

- 목록 탭 이름이 스펙 표에는 "숨기기", 화면 프레임에는 "숨김"이다. 화면 프레임(숨김)을 우선하되 확인 필요.
- ~~그룹핑이 탭 "전체"에서만 보이는지~~ → **탭 "전체"는 세 그룹, 상태 탭은 그 그룹 하나만** 그린다. 탭은 "무엇을 볼지"를 고르는 것이고 그룹은 "무엇으로 묶을지"라, 탭을 좁혀도 묶음은 그대로 두는 편이 읽기 쉽다.
- 목록에 페이지네이션이 프레임에 없다. 지금은 그룹마다 100건까지 받아 전부 그린다(`LETTER_FETCH_SIZE`). 편지가 그보다 많아지면 목록이 조용히 잘리므로 그때 페이지네이션을 붙인다.
- 답장(REPLY)은 기본 목록에서 빼고 타입 필터로 콕 집었을 때만 보여 준다. BE에 "답장 제외" 파라미터가 없어 받아온 뒤 걸러 내므로, 답장이 많아지면 그룹 건수가 100건 안에서 왜곡될 수 있다 — 위 페이지네이션과 같이 풀어야 한다.
- 발행 편지 편집의 상단 노트가 스펙은 "발행 중인 편지예요. 저장하면 바로 반영돼요", 화면 프레임(`1050:11122`)은 "발행 8.18 09:00 · 저장하면 바로 반영돼요"로 다르다. 화면 프레임 카피를 우선하되 확인 필요.
- 임시저장 화면 프레임에는 "마지막 저장 14:20"만 있고, 자동 저장(3초 후·이탈 시) 진행 중 표시는 그려져 있지 않다.
- 답장(REPLY) 열람 화면(읽기 전용, 대표 피드백·수신자 수 표시)과 모바일 에디터(한 컬럼 + 미리보기 시트), 빈 상태 화면 프레임은 없다. 스펙 텍스트만 있다.
- 미리보기 문구 60자 제한은 FE 규칙이며, BE의 title·preview 길이 제한 값은 미확정(위 BE 확인 항목).
- 화면 프레임의 폼 필드에 placeholder 텍스트는 없다(모두 예시값이 채워진 상태).
- 행 ⋯ 메뉴의 "미리보기"는 사용자 편지함 미리보기 컴포넌트가 필요해 에디터 PR에서 붙인다. 지금 메뉴에는 상태를 바꾸는 항목만 있다.
- "다시 보이기"는 프레임에 확인 창이 없지만 발행과 같은 일(사용자 편지함에 바로 나타남)이라 같은 창을 띄운다.
- 고정 비활성 사유는 툴팁 대신 항목 안 오른쪽에 적는다 — 비활성 메뉴 항목은 hover가 안 잡혀 툴팁이 뜨지 않는다.
- 모바일 프레임의 행에는 ⋯가 없다. 좁은 화면에서는 편지를 열어 바꾸는 것이 프레임의 흐름이다.
