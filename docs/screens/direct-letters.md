# 개인 편지

Figma — 화면: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=2593-425
라우트: /direct-letters · /direct-letters/[id] · /direct-letters/new
API: GET·POST admin/mailbox/direct-letters · GET admin/mailbox/direct-letters/{id} · GET admin/users (받는 사람 고르기)
BE: landit-be #212 (LAN-546)

> 운영자가 특정 사용자 1~100명에게 편지함 편지를 보낸다. 받는 사람마다 같은 편지가 한 통씩 가고, 받는 사람끼리는 서로 보이지 않는다. 푸시는 보내지 않는다. 보내면 즉시 발행되고 고치거나 회수할 수 없다.

## 화면 구성 — 새 편지 (/direct-letters/new — `2593:426`)

- 상단 줄 — 회색 안내 `편지함에만 도착해요 · 푸시는 보내지 않아요` · (spacer) · 주황 `{n}명에게 보내기`(0명이면 `보내기`)
- 2단: 왼쪽 편집(700) + 오른쪽 미리보기(340)
- 카드 `받는 사람` — 헤더 오른쪽 `{n} / 100`
  - 칩 줄 — `#{ID} {닉네임} ✕`. ✕로 뺀다
  - 추가 패널(연회색 r12) — 라벨 `추가` + 세그먼트 `사용자 목록` · `ID 붙여넣기`. 한 방법만 펼친다
    - 사용자 목록: 검색(placeholder `이메일 · 닉네임 · ID`) + 고정 표시 `활성 사용자만` · 체크 행(`#ID` · 닉네임 · 이메일) · 하단 `1–{k} / {전체}` · `더 보기` · 주황 `{n}명 추가`
    - ID 붙여넣기: 여러 줄 입력(모노) · `{n}개 인식 · 중복 {m}개 제거 · 없거나 탈퇴 {k}개 (#…)`(마지막 덩어리 빨강) · `{n}명 추가`
- 카드 `내용` — `제목` + 카운터 `{n} / 200` · `본문` — 답장과 같은 마크다운 편집기(쓰기/미리보기, 이미지 붙여넣기·끌어다 놓기)
- 미리보기 — `사용자 편지함 미리보기` · `‹ 편지함` · 칩 `편지` · 오늘 날짜 `M월 D일` · 제목 · 본문(사용자 앱과 같은 마크다운 렌더)

## 검증

- 받는 사람 1~100명(활성 사용자만 추가된다)
- 제목 앞뒤 공백 빼고 1~200자, 본문 앞뒤 공백 빼고 1자 이상. 본문의 줄바꿈은 그대로 보낸다

## BE 확인 사항 / 열린 질문

- **앱 대응 먼저** — 사용자 앱(landit-fe)이 아직 `DIRECT`를 모른다(받은 편지함 칩 표에 키가 없어 목록이 깨질 수 있다). 운영에서 보내기 전에 앱이 먼저 나가야 한다. 미리보기 칩 문구 `편지`도 앱과 맞춘다.
- **본문 형식** — BE 스웨거는 `bodyText`를 "일반 텍스트 본문"이라 적지만, 사용자 앱은 답장을 포함한 `bodyText`를 마크다운(엔터 한 번 = 줄바꿈)으로 그린다. 그래서 어드민도 피드백 답장과 같은 마크다운 편집기·미리보기를 쓴다. 이미지는 답장처럼 공개 콘텐츠 버킷에 올라간다.
- **Idempotency-Key 요청 예정** — 응답 유실 후 다시 누르면 같은 편지가 두 통 간다. 푸시 캠페인과 같은 규칙이면 프록시는 이미 헤더를 넘긴다.
- **404에 틀린 ID 목록 요청 예정** — `invalidUserProfileIds`가 오면 실패 배너에서 해당 칩을 짚을 수 있다.
- 회수(숨기기) 허용 여부 — 정책 논의. 지금 확인창 문구는 회수 불가를 전제로 쓴다.

## LAN-669 — 발송 내역 연결

- 목록은 서버 페이지(page=0부터, size=20)로 조회하고 `?page=`에 페이지를 보존한다. 제목·받는 사람 수·발송 시각을 표시하며 제목을 누르면 상세로 이동한다.
- 상세는 본문과 수신자 ID·최초 읽음 시각을 표시한다. 읽음/안 읽음 수와 비율은 상세 recipients에서 계산한다. 미리보기 날짜는 sentAt이다.
- 같은 사람에게 또 쓰기는 ID만 새 편지에 넘긴다. 현재 활성 사용자 목록과 대조하여 탈퇴·없는 사용자는 제외하고 제외 수를 알린다. 제목·본문은 복사하지 않는다.
- 로딩, 빈 목록, 조회 실패/재시도, 잘못된 상세 ID/404를 구분한다. 발송 성공 후 목록 캐시를 무효화하고 상세로 이동한다.
- Figma와 API 차이: 목록 응답에는 readCount·대표 수신자·보낸 관리자가 없다. 해당 열은 표시하지 않는다. 상세도 닉네임·이메일·보낸 관리자 없이 ID만 제공하므로 ID로 표시한다. 추가 사용자 조회를 전체 수신자마다 수행하지 않는다.
- NPS는 이번 범위에 포함하지 않는다.
