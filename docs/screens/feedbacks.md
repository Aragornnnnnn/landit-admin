## BE 동작 (AdminMailboxService.sendReplies) — 화면은 이걸 그대로 드러낸다

스펙 원문.

- POST admin/mailbox/replies {feedbackIds[], title, bodyText} — 선택한 피드백을 userProfileId로 묶는다. 답장 편지(REPLY, PUBLISHED)는 1통만 만든다
- 사용자마다 가장 오래된 피드백이 "대표". 그 사용자에게 편지 수신자 행 1개(letter → user → 대표 피드백)
- 묶인 피드백 중 처리중(PENDING)인 것만 처리완료로. 대표는 resolvedByFeedbackId=null, 나머지는 resolvedByFeedbackId=대표 피드백 ID (편지 ID가 아니다)
- 이미 처리완료인 건은 그대로 둔다. 중복 ID·없는 ID는 400/404
- 여러 사용자를 한 요청에 섞으면 각자에게 같은 답장 1통씩 간다 — API는 되지만 어드민 1차에선 안 쓴다(한 사용자씩)

## 화면 구성

스펙 원문.

- 필터 줄 — 검색(keyword) · 유형 · 상태(기본 처리중) · 기간(기본 30일) · 정렬. 우측 "처리중 12건 · 전체 128건"
- 테이블 — 유형 · 내용(1줄) · 보낸 사람(닉네임 · 이메일) · 상태 · 접수 · ›. 체크박스·선택 바 없음
- 행 클릭 → 우측 시트(520) = 그 사용자의 답장 화면: 이름·이메일·가입·사용자 상세 링크 / "답장 기다리는 피드백 N건 · 한 통으로 답장돼요" 목록(체크 기본 on) / 제목 · 본문 / 처리완료 N건 접힘 / "N건에 답장 보내기" / 결과 안내 한 줄
- 모바일 — 목록은 흰 그룹 리스트, 행 탭 → 같은 내용의 전체 화면(뒤로가기), CTA 하단 고정

- **답장 템플릿 (운영자 결정 · 2026-08-26, 프레임에 없음)** — 함께 답장 아래·제목 입력 위에 "템플릿" 칩 줄. 팀이 확정한 공식 답장 문구 7종(응원 감사 · 기능 접수 · 기능 반영 · 반영 어려움 · 버그 확인 중 · 버그 수정 완료 · 문의 답변)이며, `OO`·괄호 자리는 적용 후 본문에서 직접 채운다. **유형에 맞는 템플릿이 미리 채워져 시작하고, 칩도 그 유형에 어울리는 것(+직접 만든 것)만 보인다**(문의→문의 답변 1개, 응원→응원 감사 1개, 버그→확인 중·수정 완료 2개, 기능 요청→접수·반영·반영 어려움 3개) — 적용된 칩은 진하게 표시. 템플릿 그대로면 다른 칩으로 확인 없이 바꾸고, 직접 고친 글자가 있을 때만 "쓰던 내용을 지우고 템플릿을 적용할까요?" 확인 창을 거친다. 칩 끝의 "관리"에서 어드민 안에서 문구를 고치고 추가·삭제·기본값 복원할 수 있다 — BE 저장 API가 없어 **이 브라우저(localStorage)에만 유지**되고, 팀 공유 기본값은 `_model/reply-templates.ts` 배열이 진실이다({닉네임} 자리 표시 지원). 공지용 템플릿(일반 공지·업데이트·점검)은 편지 에디터에 붙어 있다. PNG·JPG·WEBP·GIF만 받는다 — 이미지가 아닌 파일은 조용히 무시하고, SVG처럼 허용 형식이 아닌 이미지와 10MB 초과는 올리지 않고 토스트로 알린다(SVG는 스크립트를 품을 수 있어 관리자 업로드 경로에서 열지 않는다). 자리표시는 문자열 치환이 아니라 삽입 위치를 기억해 바꾼다(같은 자리표시가 여러 개일 수 있어서). 전송 API·본문 상한(1,000자)은 그대로다 — 이미지 마크다운이 상한을 잡아먹는 문제는 BE·앱 한도 확인 뒤 별도 이슈.
