# 푸시 알림 (캠페인)

Figma — 화면: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=2176-274 · 스펙: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=2186-429

API: `/api/v1/admin/push-campaigns*` (아래 데이터) · GET admin/users?active&pushConsent
BE: landit-be #174 (LAN-462) · `docs/tasks/LAN-462/design.md`

> 관리자가 제목·본문·딥 링크로 캠페인을 만들고, 내 기기로 테스트한 뒤 전체 또는 선택 사용자에게 지금 발송하거나 한국 시간으로 예약한다. 생성 후 내용과 대상은 바꿀 수 없다 — 바꾸려면 새 캠페인을 만든다.

## 화면 구성

### 목록 (/push-campaigns — `2176:275`)

- 상단 컨트롤 행 — 세그먼트 탭 `전체` · `예약` · `발송됨` · `초안`, Select `상태: 전체`, 오른쪽 주황 버튼 `새 푸시 만들기`
- 배너 `다음 발송` — 시계 아이콘 · "내일 (토) 19:00 · {제목}" · "예상 {n}명 · {m}개 기기" · 버튼 `상세 보기`. 예약된 캠페인이 없으면 안 그린다
- 표(흰 카드 r20) — 헤더 `캠페인 {n}`. 열: 제목(flex) · 대상(130) · 상태(100) · 발송·예약(130) · 결과(170) · 생성(90) · ⋯(24)
  - 대상 셀: `전체` / `선택` + 회색 보조 "1,204명 · SQL" / "9,412 기기"
  - 상태 셀: 점 + 라벨(아래 "상태 배지")
  - 발송·예약 셀: 예약이면 "09.12 19:00 예약", 발송이면 시작 시각, 취소면 "08.30 19:00 (취소)", 초안은 `—`
  - 결과 셀: 발송 중은 진행 바 + "62% · 5,820", 완료는 "성공 9,102 · 실패 44"(실패는 빨강), 나머지 `—`
  - 행 클릭 → 상세. ⋯는 상세와 같은 액션(예약 취소 등)
- 페이지 줄 — 왼쪽 "1–6 / 6", 오른쪽 숫자 페이지 + ‹ › (`shared/ui/Pagination`). 한 장이면 안 그린다

### 새 푸시 (/push-campaigns/new — `2177:285`)

- 상단 액션바 — `← 목록` · 칩 `초안` · (spacer) · 주황 `초안 저장`
- 2단: 왼쪽 편집(700) + 오른쪽 미리보기(340)
- 카드 `내용`
  - `제목` 입력 + 카운터 "17 / 255"
  - `본문` 입력(여러 줄) + 카운터 "46 / 500"
  - `딥 링크` 입력(모노)
  - 블록 `UTM 자동 붙이기` — 스위치(기본 on) · 칩 `source push` · `medium admin` · `campaign survey_premium_0912`(수정 가능, 오렌지 테두리) · 최종 링크 한 줄(모노, 말줄임) + `복사`
- 카드 `대상`
  - 세그먼트 `전체 사용자` / `선택한 사용자`
  - 타일 `예상 대상` — "1,204명 · 1,251개 기기" + 오른쪽 "발송할 때 다시 계산돼요"
  - **대상 목록** — 한 줄씩: 아이콘 · 이름(SQL / 직접 선택 / 붙여넣기 / 제외) · 수(오렌지, 제외는 빨강) · 요약(말줄임) · `수정` · ✕. 줄무늬 없음(hover만)
  - **대상 추가 패널**(연회색 r12) — 라벨 `대상 추가` + 세그먼트 `사용자 목록` · `ID 붙여넣기` · `SQL` · `제외`. 한 방법만 펼친다
    - 사용자 목록: 검색 입력(placeholder "이메일 · 닉네임 · ID") + 필터 칩 `활성` `알림 허용`(기본 on) · 체크 행(#ID · 닉네임 · 이메일) · 하단 "1–4 / 1,284" · `더 보기` · 주황 `{n}명 추가`
    - ID 붙여넣기: 여러 줄 입력(모노) · 아래 "5개 인식 · 중복 1개 제거" · `추가`
    - SQL: 여러 줄 입력(모노) · `조회` · 결과 "1,192명" · `추가`
    - 제외: ID 여러 줄 입력 · `추가`
  - 전체 사용자를 고르면 대상 목록·추가 패널을 숨기고 예상 대상 타일만 남긴다
- 미리보기 열 — 세그먼트 `iOS` / `Android` + 폰(아래 "미리보기 기준"). 제목·본문 입력이 즉시 반영된다

### 상세 (/push-campaigns/[id] — `2177:354` 초안 · `2177:423` 완료)

- 상단 액션바 — `← 목록` · 상태 칩 · "{만든 사람} · {생성 시각}" · (spacer) · 상태별 버튼
  - 초안: `내게 테스트 발송`(outline) · `예약 발송`(secondary) · `지금 발송`(primary)
  - 예약됨: `예약 취소`(destructive outline)
  - 발송 중·완료·취소됨: `같은 내용으로 새 푸시`(outline) — 내용을 채운 새 푸시 화면으로
- 왼쪽
  - 초안: 카드 `예상 대상` — 타일 `예상 대상 1,204명` · `활성 기기 1,251개`(보조 "iOS 812 · Android 439"는 API에 없어 생략) · `대상 유형 선택`(보조 "발송 시 SQL 재조회")
  - 완료·발송 중: 카드 `발송 결과` — 타일 `대상 9,412`(보조 "9,146명") · `성공`(초록) · `실패`(빨강) · `대기` · `제외` + 분포 바(초록·빨강·회색) + 범례
  - 카드 `내용` — 제목 · 본문 · 딥 링크(모노, UTM 포함 전체)
  - 카드 `대상 구성`(선택) — SQL 조회 {n}명 + SQL 한 줄 말줄임 · 직접 선택 {n}명 + "#1284 수진 · … · +9명" · 붙여넣은 ID · 제외. 전체면 카드 `대상` — "전체 사용자"
- 오른쪽 — 미리보기(iOS/Android 세그먼트) + 카드 `진행`: 초안 생성 → 발송(또는 예약 시각) → 완료. 끝난 단계 초록 점, 다음 단계 오렌지, 미정 회색

### 지금 발송 확인 (`2183:363`)

- 제목 `지금 1,204명에게 보낼까요?`
- 본문 `1,251개 기기로 보내요. 보낸 푸시는 되돌릴 수 없어요.`
- 요약 블록(연회색) — 제목 · 본문 · 이동(딥 링크)
- 버튼 `취소` · 주황 `지금 발송`

### 예약 발송 (`2183:521`)

- 제목 `예약 발송` + ✕
- `날짜` 입력 "2026-09-12 (토)" · `시간` 입력 "19:00"
- 빠른 선택 칩 `오늘 19:00` · `내일 09:00` · `내일 19:00` · `다음 월요일 09:00`
- 요약 타일(오렌지 연) — "9월 12일 (토) 오후 7:00에 발송" · "예상 1,204명"
- 버튼 `취소` · 주황 `예약하기`

### 모바일 목록 (`2183:679`)

- 타이틀 `푸시 알림` + 요약 "예약 1 · 발송 중 1 · 완료 2" + 주황 `새 푸시`
- 세그먼트, 배너(두 줄), 카드 목록 — 제목 + 상태(오른쪽), 메타 한 줄("선택 1,204명 · SQL · 09.12 19:00 예약"), 발송 중은 진행 바, 완료는 성공·실패

## 데이터

| 사용자 목록  | GET admin/users?active=true&pushConsent=true&page&size → items[].pushPermissionStatus, totalCount, totalPages (LAN-462에서 추가, [users.md](users.md))                                                                                                                                                              |

## 상태

| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상태 배지 | DRAFT `초안`(회색, 점 없음) · SCHEDULE_PENDING/SCHEDULED `예약됨`(검정 점) · PENDING/QUEUED/SENDING `발송 중`(오렌지 점) · COMPLETED `완료`(초록 점) · CANCELLED `취소됨`(회색, 점 없음)  |

## BE 확인 사항 / 열린 질문

- **develop 배포 전** — landit-be #174 머지(2026-09-10). 배포 전 IaC #37·#38(EventBridge Scheduler·DLQ)와 읽기 전용 DB 계정(`landit_push_reader`)·Supabase CA 설정 필요. 스웨거에 올라오면 `pnpm api:types` 재생성 후 `schema-patch.ts` 임시 타입 제거.
- 프록시가 `Idempotency-Key` 헤더를 BE까지 넘겨야 한다(어드민 PR 2에서 추가).
- `createdAt`·`completedAt`이 LocalDateTime(오프셋 없음)이라 BE 서버 시간대에 따라 표시가 어긋날 수 있다. 다른 화면과 같은 취급 — BE가 Instant로 바꾸면 그대로 따라간다.
- 활성 기기 수의 플랫폼 분리(iOS/Android)는 API에 없어 화면에서 뺐다(Figma 초안 상세 타일의 보조 문구).
- UTM은 BE 서버 푸시 규칙(`utm_source=push&utm_medium=notification`, `ScheduledNotificationContent`·`PushQueueMessageHandler`)에 맞췄다. BE가 LAN-184 계획대로 `utm_source=landit&utm_medium=push`로 바꾸면 `deep-link.ts` 상수 둘을 같이 바꾼다. `admin_` 접두사는 FE 규칙.
