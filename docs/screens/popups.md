# 팝업 관리 (LAN-740)

`/popups`에서 앱에 노출할 팝업을 등록·수정한다. 알림 그룹에 팝업 메뉴를 추가한다.

- 목록은 최신 등록순으로 제목, 켜짐·꺼짐, 노출 기간(KST), 우선순위를 표시한다. 켜져 있어도 기간 밖이거나 우선순위가 낮으면 노출되지 않는다.
- 기간은 시작 포함·종료 제외다. 동시에 해당하면 우선순위가 높은 것, 같으면 ID가 큰 것 하나를 서버가 선택한다.
- 등록·수정은 같은 다이얼로그를 사용한다. 제목(1~~200자), HTTPS 이미지, 선택 링크(HTTPS 또는 `/` 앱 경로), 켜짐·꺼짐, 시작·종료 시각, 우선순위(0~~2147483647 정수)를 편집한다.
- 시각은 브라우저 시간대와 무관하게 한국 시간(KST)으로 입력·표시하고, API에는 시간대가 포함된 ISO 문자열을 전송한다. 수정하지 않은 시각의 정밀도는 유지한다.
- 이미지는 PNG/JPEG/WebP/GIF, 확장자와 MIME 일치, 0바이트 초과·10 MiB 이하만 받는다. 기존 콘텐츠 이미지 presign API로 업로드하고 결과 이미지와 주소를 보여준다. HTTPS 이미지 주소 직접 입력도 허용한다.
- 저장 전 제목·기간·켜짐 상태를 확인한다. 꺼짐은 다음 앱 조회부터 제외됨을 안내한다. 업로드·저장 중 닫기와 중복 제출을 막는다. 실패하면 입력을 유지하며 다시 시도할 수 있다.
- 변경한 필드만 PATCH한다. 링크를 비우면 명시적인 null로 제거한다. 수정하지 않은 필드와 서버 시각은 보존한다.
- 입력이 있는 창을 닫으려 하면 폐기 확인을 받는다. 빈 목록·로딩·조회 실패 재시도 상태를 제공한다.

## API와 배포 순서

landit-be PR #319의 `GET/POST /api/v1/admin/popups`, `PATCH /api/v1/admin/popups/{popupId}`를 기존 인증 프록시로 호출한다. BE 마이그레이션/API 배포 후 사용 가능하다. 앱의 실제 팝업 렌더링은 landit-fe의 별도 연동이다.

## 디자인 근거

2026-10-22 Figma `🛠 어드민` 페이지(1050:1576) 메타데이터에서 팝업 관리 전용 프레임은 확인되지 않았다(푸시 알림의 Android 헤드업 팝업 설명만 존재). 기존 셸과 공통 카드·입력·다이얼로그 토큰을 사용한다. 전용 Figma 원본 이미지는 없으므로 구현 스크린샷만 첨부하며 시안 일치를 주장하지 않는다.

## 검증 기록

- Node 22에서 ESLint, TypeScript, 프로덕션 빌드와 Vitest 전체 577개를 통과했다. 팝업 입력 규칙·이미지 제한 21개, 화면 동작 3개를 포함한다.
- 독립 리뷰에서 발견한 백그라운드 재조회 실패 시 입력 유실과 기존 마이크로초 기간 재검증 오류를 재현 테스트 후 수정했다. `/popups` 메뉴 누락도 보완했고 재검토에서 추가 결함은 없었다.
- 데스크톱 1440px·모바일 390px에서 목 API로 편집창·이미지 미리보기·스크롤을 확인했다. 실제 BE·S3·사용자 앱·운영 DB 검증이나 배포는 수행하지 않았다.
- `schema.d.ts`는 BE PR #319 작업 트리의 통합 테스트가 내보낸 `build/openapi.json`에서 기존 `api:types` 스크립트로 재생성했다. 생성 파일이며 수동 타입 정의를 추가하지 않았다.
- Playwright 브라우저에서 신규 등록 POST(필수 필드·KST→UTC), 콘텐츠 이미지 presign/PUT 목 업로드, 링크 제거·끄기 PATCH가 성공하고 목록이 갱신되는 것을 확인했다. 증거 이미지는 `docs/images/screens/popups*.png`에 보관한다.
