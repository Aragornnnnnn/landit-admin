# 팝업 관리 (LAN-740)

`/popups`에서 앱에 노출할 팝업을 등록·수정한다. 알림 그룹에 팝업 메뉴를 추가한다.

- 목록은 최신 등록순으로 제목, 켜짐·꺼짐, 노출 기간(KST), 우선순위를 표시한다. 켜져 있어도 기간 밖이거나 우선순위가 낮으면 노출되지 않는다.
- 기간은 시작 포함·종료 제외다. 동시에 해당하면 우선순위가 높은 것, 같으면 ID가 큰 것 하나를 서버가 선택한다.
- 등록·수정은 같은 다이얼로그를 사용한다. 제목(1~~200자), HTTPS 이미지, 선택 링크(HTTPS 또는 `/` 앱 경로), 켜짐·꺼짐, 시작·종료 시각, 우선순위(0~~2147483647 정수)를 편집한다.
- 시각은 브라우저 시간대와 무관하게 한국 시간(KST)으로 입력·표시하고, API에는 시간대가 포함된 ISO 문자열을 전송한다. 수정하지 않은 시각의 정밀도는 유지한다.
- 이미지는 PNG/JPEG/WebP, 확장자와 MIME 일치, 0바이트 초과·10 MiB 이하만 받는다. 기존 콘텐츠 이미지 presign API로 업로드하고 결과 이미지와 주소를 보여준다. HTTPS 이미지 주소 직접 입력도 허용한다.
- 저장 전 제목·기간·켜짐 상태를 확인한다. 꺼짐은 다음 앱 조회부터 제외됨을 안내한다. 업로드·저장 중 닫기와 중복 제출을 막는다. 실패하면 입력을 유지하며 다시 시도할 수 있다.
- 변경한 필드만 PATCH한다. 링크를 비우면 명시적인 null로 제거한다. 수정하지 않은 필드와 서버 시각은 보존한다.
- 입력이 있는 창을 닫으려 하면 폐기 확인을 받는다. 빈 목록·로딩·조회 실패 재시도 상태를 제공한다.

## API와 배포 순서

landit-be PR #319의 `GET/POST /api/v1/admin/popups`, `PATCH /api/v1/admin/popups/{popupId}`를 기존 인증 프록시로 호출한다. BE 마이그레이션/API 배포 후 사용 가능하다. 앱의 실제 팝업 렌더링은 landit-fe의 별도 연동이다.

## 디자인 근거

2026-10-22 Figma `🛠 어드민` 페이지(1050:1576) 메타데이터에서 팝업 관리 전용 프레임은 확인되지 않았다(푸시 알림의 Android 헤드업 팝업 설명만 존재). 기존 셸과 공통 카드·입력·다이얼로그 토큰을 사용한다. 전용 Figma 원본 이미지는 없으므로 구현 스크린샷만 첨부하며 시안 일치를 주장하지 않는다.

## 검증 기록

- Node 22에서 ESLint, TypeScript, 프로덕션 빌드와 Vitest 전체 578개를 통과했다. 팝업 입력 규칙·이미지 제한 22개, 화면 동작 3개를 포함한다.
- 독립 리뷰에서 발견한 백그라운드 재조회 실패 시 입력 유실과 기존 마이크로초 기간 재검증 오류를 재현 테스트 후 수정했다. `/popups` 메뉴 누락도 보완했고 재검토에서 추가 결함은 없었다.
- 데스크톱 1440px·모바일 390px에서 목 API로 편집창·이미지 미리보기·스크롤을 확인했다. 실제 BE·S3·사용자 앱·운영 DB 검증이나 배포는 수행하지 않았다.
- `schema.d.ts`는 BE PR #319 작업 트리의 통합 테스트가 내보낸 `build/openapi.json`에서 기존 `api:types` 스크립트로 재생성했다. 생성 파일이며 수동 타입 정의를 추가하지 않았다.
- Playwright 브라우저에서 신규 등록 POST(필수 필드·KST→UTC), 콘텐츠 이미지 presign/PUT 목 업로드, 링크 제거·끄기 PATCH가 성공하고 목록이 갱신되는 것을 확인했다. 증거 이미지는 `docs/images/screens/popups*.png`에 보관한다.

- 후속 독립 리뷰에서 발견한 GIF 업로드 계약 불일치를 수정했다. 백엔드가 지원하는 JPEG·PNG·WebP만 허용하고 GIF 거부 회귀 테스트를 추가했다.
- GIF 차단 수정 후 전체 테스트 578개·린트·타입 검사를 통과했다. 브라우저에서 파일 필터를 우회해 GIF를 선택해도 오류 안내와 함께 presign/업로드 요청이 발생하지 않는 것을 확인했다.

## 사용자 숨김 (LAN-740 후속)

- 팝업 편집창에서 이메일·닉네임·ID로 활성 사용자를 검색하고 최대 1000명을 숨김 대상으로 선택한다. 검색은 서버 페이지 조회를 사용한다.
- 선택한 사용자는 해당 팝업의 노출 후보에서 제외한다. 다른 후보가 있으면 다음 우선순위 팝업을, 없으면 아무 팝업도 보여주지 않는다.
- 숨김 설정이 있는 팝업은 비로그인 요청에도 노출하지 않는다. 기존 숨김 없는 팝업과 공개 응답 형태는 유지한다.
- 생성 시 `excludedUserIds`를 보내고, 수정 시 변경된 경우에만 보낸다. 빈 배열은 전체 해제, 생략은 기존 유지다. 저장 확인창에 숨길 사용자 수를 표시한다.
- 공지와 같은 월간·연간·100일 이용권·무료 체험·미구독·관리자 부여·기타 구독 유형을 복수 선택한다. 개별 사용자 또는 선택 유형 중 하나라도 일치하면 숨긴다. 현재 구독 상태는 팝업 조회 시 판단한다.
- `excludedAudiences`도 생성 시 전송하며 PATCH 생략은 유지, 빈 배열은 해제다. 선택 순서만 달라지면 변경으로 보지 않는다. 확인창에는 선택한 유형 이름을 표시한다. BE의 유형별 숨김 API를 먼저 전체 배포한 뒤 어드민을 반영한다.

### 사용자 숨김 검증

- Node 22 / pnpm 10에서 린트·타입 검사·프로덕션 빌드와 전체 테스트 584건 통과. 실제 팝업 편집창에서 같은 사용자를 해제 후 재선택하면 변경 없음으로 판단하며 빈 PATCH를 보내지 않는다.
- 독립 리뷰에서 발견한 배열 순서와 집합 비교의 불일치를 수정했다. 폼 내부 사용자 검색 재시도가 저장을 제출하지 않도록 공통 오류 버튼을 `type="button"`으로 명시하고 회귀 검증했다.
- Playwright 목 API로 1440px·390px의 검색·선택·확인창과 `PATCH {excludedUserIds:[7,12]}` 저장을 확인했다. `docs/images/screens/popup-exclusions-*.png`는 가상 사용자로 만든 구현 증거다. 전용 Figma 프레임 부재는 기존 디자인 근거와 같으며 Figma 일치를 주장하지 않는다.
- `schema.d.ts`는 BE LAN-740 사용자 숨김 구현의 로컬 `build/openapi.json`으로 생성했다. 생성 파일이며 변경되지 않은 API를 포함한 현재 develop 계약도 함께 갱신한다.
- 실제 서버 저장·운영 DB 적용·배포·실기기 노출은 수행하지 않았다.

### PR CI의 기존 의존성 취약점 보완

- PR CI가 Next.js 16.3.8의 기존 취약점 3건에서 중단되어 `next`와 `eslint-config-next`를 16.4.1로 맞췄다. [이미지 최적화](https://github.com/advisories/GHSA-2464-fhr4-w9xw), [캐시 함수](https://github.com/advisories/GHSA-673q-mjm6-r5xr), [Server Actions](https://github.com/advisories/GHSA-p3m5-59mp-jv5r) 공식 권고의 수정 버전이다.
- `minimumReleaseAge`와 빌드 스크립트 허용 규칙을 유지했다. 독립 리뷰에서 버전 일치·lockfile·정책 보존을 확인했으며 확정 결함은 없었다.
- 갱신 후 `pnpm audit --prod --audit-level=high` 알려진 취약점 0건, 전체 테스트 584건·포맷·린트·타입 검사·프로덕션 빌드 통과. 브라우저 스크린샷 검증은 앞선 16.3.8 실행 결과다.

### 공지와 동일한 구독 유형 숨김 검증

- 공지와 팝업이 같은 `SubscriptionAudienceFields`를 사용한다. 7개 선택지·복수 선택·저장 확인과 개별 사용자 숨김을 함께 지원한다.
- Node 22 / pnpm 10에서 전체 588개 테스트, 린트·타입 검사·프로덕션 빌드 통과. 유형만 해제해도 개별 사용자 설정을 보존하며, 같은 유형을 순서만 바꿔 선택하면 PATCH하지 않는다.
- 별도 `popup_exclusions_review` 에이전트가 UI·생성 계약·배포 순서를 독립 리뷰했고 확정 결함은 없었다. 공지·팝업 관련 55개 테스트를 독립 실행해 통과했다.
- Playwright 모의 API로 1440px·390px의 7개 옵션과 저장 확인을 확인했다. 재편집 시 월간·연간이 유지되고, 100일 이용권 추가 시 `PATCH {excludedAudiences:["MONTHLY","YEARLY","PASS_100_DAYS"]}`만 전송됨을 검증했다. `docs/images/screens/popup-audiences-*.png`는 가상 사용자로 만든 화면이다.
- BE LAN-740 구독 유형 숨김 구현의 `build/openapi.json`에서 API 타입을 재생성했다. 실제 서버 저장·배포·실기기 노출은 수행하지 않았다. BE 전체 교체 후 어드민 배포가 필요하다.
