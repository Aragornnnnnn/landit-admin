# 콘텐츠 생성·검수

LAN-695. 보고서용 로컬 재현 화면을 실제 관리자 API에 연결한다. `/content-batches`에서 제작 배치 목록, 생성 조건, 라인업 확인, 초안 검수·재생성·승인을 이어서 제공한다.

## 화면과 데이터

- 기존 관리자 셸과 Pretendard, 회색·흰색 배경, 오렌지 주 행동·선택 상태를 사용한다. 별도 Figma 시안은 없으며 사용자가 기존 로컬 화면을 실제 develop에서 사용할 수 있게 요청했다. 로컬 재현 코드·운영 DB 고정 자료·가짜 검수 결과는 포함하지 않는다.
- 목록 페이지와 선택 배치·Day는 URL의 `page`, `batch`, `draft`에 보관한다. 이전/다음 페이지, 빈 목록과 오류 재조회 제공.
- 생성 입력: Day 수 1~30, 클로이·마르코·테디별 수의 합이 Day 수와 일치해야 함. 요청 메모 최대 2,000자. 다음 Day는 서버 조회값을 표시하고 직접 지정하지 않음. 생성 비용이 발생함을 확인창에서 안내. `autoProceed=false`로 라인업 확인 후 진행.
- LINEUP_READY: 시나리오 제목·카테고리·난이도·대화 시작 주체·캐릭터·대화 구성을 확인. 의견을 입력해 라인업 재생성 또는 생성 진행. 직접 JSON 편집은 제공하지 않음.
- 생성 중에는 배치 상태와 완료 Day 수를 표시. 서버 상태를 3초마다 다시 조회하고 종료 상태에서는 중지. 검수 배치의 개별 Day 재생성도 조회를 지속. 진행률이나 예상 시간을 임의로 만들지 않음.
- 질문·표현을 세 단계 난이도로 확인하고 별점 문구와 검수 근거·코멘트를 함께 읽는다. 생성 중의 누락 자료는 오류/실행 중/기록 없음으로 구분.
- 자동 검사, 독립 AI 검수와 담당자 코멘트는 저장된 응답 그대로 표시. null·잘못된 형식과 빈 배열(지적 없음)을 구분. 누락된 검수를 통과로 표시하지 않음.

## 검수·승인

- 배치 GENERATING/REVIEW_READY, Day REVIEW_READY/NEEDS_FIX/OK이면 OK/FIX 저장 가능. FIX에는 의견 필수. 의견은 현재 선택 Day에만 적용하며 대상 변경 시 초기화.
- REVIEW_READY 배치에서는 Day별 전체·난이도별 질문과 표현·표현만·별점 문구 재생성 가능. 실행 전에 대상과 비용 발생을 확인. 서버의 `scope` 계약 그대로 요청.
- 배치 승인: REVIEW_READY이고 모든 Day가 OK일 때만 버튼 활성화. Day 수와 텍스트 승인 범위를 확인창에 명시. 승인 시 표현 ID가 예약되며 이미지·음성 생성 또는 운영 발행은 수행하지 않음.
- 작업 중 중복 제출을 막고 실패하면 확인창과 입력 유지. 성공은 API 응답 이후에만 표시하고 관련 목록·상세·다음 Day를 갱신. 409 등은 서버 오류 메시지를 표시한 뒤 현재 상태 재조회.
- 모든 변경은 기존 same-origin 프록시 사용. 토큰·인증·CSRF·캐시 정책 변경 없음. 화면 권한은 BE 판정을 따름.

## 검증과 범위

- API 경로·요청 계약·변경 실패 및 상태 갱신, FIX 의견 필수, 모든 Day OK 이전 승인 차단, 재생성 중 polling, 검수 기록 누락의 의미를 테스트.
- 브라우저에서는 API 경계를 로컬 응답으로 대체해 생성부터 승인까지 확인. 실제 develop AI 작업 실행 여부는 별도 기록하며 mock 검증을 운영/배포 검증으로 표현하지 않음.
- BE·DB 스키마 변경 없음. 새 승인 API나 자산 발행 기능은 추가하지 않음.
