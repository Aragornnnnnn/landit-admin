## 데이터

스펙 그룹명 "카드 ↔ 데이터". 원문 표를 그대로 옮긴다.

| 카드                 | 값 · 출처                                                                                                    | 클릭              |
| -------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------- |
| 답장 기다리는 피드백 | `feedbacks?status=PENDING&size=1` → totalElements · 오늘 = createdFrom=오늘                                  | 피드백(처리중)    |
| 가장 오래 기다린 건  | `feedbacks?status=PENDING&sort=OLDEST&size=1` → 첫 항목의 createdAt 경과·유형·닉네임                         | 그 건의 답장 시트 |
| 이번 주 가입         | users 최신순 페이지를 createdAt이 7일 전 아래로 내려갈 때까지 넘기며 카운트(보통 1~3장) · 지난주도 같은 방식 | 사용자            |
| 피드백 접수 7일      | 날짜별 createdFrom/To 로 7번(size=1) → totalElements 막대. 오늘 막대 진하게                                  | 피드백(기간 필터) |
| 처리중 유형별        | type별 4번(`status=PENDING&size=1`) → totalElements                                                          | 피드백(유형 필터) |
| 앱 버전              | GET admin/app-versions                                                                                       | 앱 버전           |
| 지금 편지함 맨 위    | `letters?publicationStatus=PUBLISHED&size=3` (고정 먼저) + DRAFT 수                                          | 공지·업데이트     |
| 최근 피드백          | `feedbacks?sort=NEWEST&size=5`                                                                               | 그 건의 답장 시트 |

- 요청 수: 진입 시 약 20개(전부 size=1 카운트라 가볍다). 30분 캐시 + 새로고침 버튼. 집계 API가 생기면 이 표를 그걸로 교체.

## 인터랙션

스펙에 별도 "인터랙션" 그룹은 없다. "카드 ↔ 데이터" 표의 "클릭" 열이 인터랙션 정의다.

| 요소                                       | 클릭 결과                                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 답장 기다리는 피드백 카드                  | 피드백 화면(처리중 필터)                                                                                                  |
| 가장 오래 기다린 건 카드                   | 그 건의 답장 시트                                                                                                         |
| 이번 주 가입 카드                          | 사용자 화면                                                                                                               |
| 피드백 접수 7일 차트                       | 피드백 화면(기간 필터)                                                                                                    |
| 처리중 유형별 바                           | 피드백 화면(유형 필터)                                                                                                    |
| 앱 버전 카드 / "앱 버전 ›"                 | 앱 버전 화면                                                                                                              |
| 지금 편지함 맨 위 카드 / "공지·업데이트 ›" | 공지·업데이트 화면                                                                                                        |
| 최근 피드백 행                             | 그 건의 답장 시트                                                                                                         |
| "피드백 ›" / 모바일 "전체 보기"            | 피드백 화면 (화면 프레임의 링크 카피에서 유추, 스펙 표에는 별도 항목 없음)                                                |
| 새로고침 버튼                              | 30분 캐시를 무시하고 다시 불러온다 (스펙 문장 "30분 캐시 + 새로고침 버튼"). 화면 프레임에는 버튼 위치가 그려져 있지 않음. |
| 모바일 햄버거                              | 드로어 열림 (프레임 `1050:8006`). "✕" 또는 딤 탭으로 닫힘은 스펙에 명시 없음.                                             |

## 상태

| 상태    | 표시                                                           |
| ------- | -------------------------------------------------------------- |
| 로딩    | 카드별 독립 스켈레톤(하나 느려도 나머지 먼저 그림)             |
| 빈 상태 | 미답변 0 → 숫자 0. 최근 피드백 0 → "아직 받은 피드백이 없어요" |
| 오류    | 카드 단위 인라인 오류 + 다시 시도                              |

## 모바일

- 2×2 요약 카드 → 앱 버전 → 최근 피드백 리스트. CTA 없음(현황판)

## 검증

스펙에 없음.

## BE 확인 사항 / 열린 질문

스펙 그룹 "BE 있으면 추가할 것" 원문.

- 가입자·DAU·완료율 집계 → 앱인토스처럼 차트 카드 자리(요약 카드 아래)

스펙 텍스트와 화면 프레임 사이 차이, 스펙에 명시가 없는 것.

- 집계 API가 없어 모든 숫자를 목록 API `size=1` 카운트로 만든다. 집계 API가 생기면 "카드 ↔ 데이터" 표를 그걸로 교체한다.
- "이번 주 가입"은 users 최신순 페이지를 넘기며 세는 방식이라 가입자가 많아지면 페이지 수가 늘어난다. 이 기준(7일 전 이후 createdAt)이 지난주 카운트에도 같은 방식으로 적용된다.
- 새로고침 버튼은 스펙 문장에는 있으나 데스크톱·모바일 화면 프레임 어디에도 그려져 있지 않다. 위치·형태 확인 필요.
- 모바일/대시보드(`1050:7905`)와 드로어 프레임(`1050:8006`)의 뒤 화면이 다르다. 전자는 요약 카드 3개(답장 기다리는 피드백·가장 오래 기다린 건·이번 주 가입) + 피드백 접수 막대, 후자는 요약 카드 2개(답장 기다리는 피드백·임시저장 편지) + 막대 없음, 최근 피드백 행에 유형·상태 칩. 스펙 텍스트("2×2 요약 카드 → 앱 버전 → 최근 피드백 리스트")는 전자에 가깝다. 모바일/대시보드 프레임을 우선하되 확인 필요.
- 모바일에는 "지금 편지함 맨 위" 카드와 "처리중 유형별" 섹션이 없다. 의도적 생략인지 확인 필요.
- 상태 칩(처리중/처리완료)의 점 색상은 데스크톱 프레임에서 두 종류로 구분되어 있으나 정확한 색값은 SVG 에셋이라 본 문서에 없다. 피드백 화면 스펙의 칩 정의를 따른다.
- 보낸 사람 열의 이메일은 화면 예시처럼 마스킹(`sujin***@gmail.com`)해서 보여주는지 스펙에 명시가 없다.
- 데스크톱 안내 한 줄의 "마지막 14:20"은 캐시 시각(마지막 새로고침)으로 보이나 스펙에 명시가 없다.
