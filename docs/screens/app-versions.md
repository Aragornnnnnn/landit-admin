# 앱 버전

Figma — 화면: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=1050-11870 · 스펙: https://www.figma.com/design/3LwSPCntVV55PU1CIcXbVN/?node-id=1050-12661
라우트: /app-versions
API: GET admin/app-versions · PATCH admin/app-versions/{IOS|ANDROID} · (앱 쪽) GET /app-versions/check?platform&versionName

> 앱이 켜질 때 비교하는 업데이트 정책. 필드를 API 이름이 아니라 결과별로 묶는다 — [강제 업데이트: 최소 지원 버전 + 문구] / [업데이트 권유: 최신 버전·빌드 + 문구] / [기록: 릴리즈 노트·배포일]. 그룹 설명 한 줄 + "앱 화면 미리보기"가 결과를 보여준다. 저장 확인 창에 "1.3.0 미만은 강제 업데이트를 보게 돼요" 식 영향 문장.

## 화면 구성

### 데스크톱 기본 (1050:11871)

공통 셸: 사이드바(280px, 내비 "앱 버전" 활성) + 메인(상단바 제목 "앱 버전" 28px + content 좌우 48px).

- 페이지 안내(회색 13px): "저장하면 앱에 바로 반영돼요. 앱은 켜질 때 자기 버전을 아래 기준과 비교해서 강제 업데이트 / 권유 / 없음 중 하나를 보여줘요."
- 플랫폼 카드 2장 가로(각 flex 1, 흰 배경, 둥근 20px, 패딩 24/22, 내부 간격 16px)
  - 카드 헤더: 플랫폼명 "iOS" / "Android"(19px 굵게) · 오른쪽 상태 표시 = 점(6px) + "앱에 반영 중"(12px)
  - 그룹/강제 업데이트 (연회색 #F9FAFB 박스, 둥근 14px, 패딩 18/16)
    - 헤더 행: "강제 업데이트"(14px 미디엄) · 오른쪽 텍스트 링크 "앱 화면 미리보기"(12px)
    - 설명: "이 버전보다 낮은 앱은 스토어로만 갈 수 있어요"
    - 필드 "최소 지원 버전" — 입력(흰 배경, 둥근 10px, 패딩 14/11) 예: 1.3.0
    - 필드 "앱에 보여줄 문구" — 입력 예: 안정적인 이용을 위해 최신 버전으로 업데이트해 주세요
  - 그룹/업데이트 권유 (소프트)
    - 헤더 행: "업데이트 권유 (소프트)" · "앱 화면 미리보기"
    - 설명: "최소 지원 이상, 최신 미만인 앱에 닫을 수 있는 안내가 떠요"
    - 가로 2필드: "최신 버전"(예: iOS 1.4.2 / Android 1.4.1) · "빌드 번호"(예: iOS 58 / Android 57)
    - 필드 "앱에 보여줄 문구" — 예: 새 기능이 추가됐어요. 업데이트하고 만나보세요
  - 그룹/기록
    - 헤더: "기록" · 설명 "판정에는 쓰이지 않아요" (미리보기 링크 없음)
    - 필드 "릴리즈 노트" — 여러 줄 입력. 예: "· 편지함이 생겼어요 / · 마이크 오류 수정"(iOS), "· 스트릭 달력 / · 알림 안정화"(Android)
    - 필드 "배포일" — 예: 2026-08-12 10:00 (iOS), 2026-08-10 11:00 (Android)
  - 카드 푸터 행: 왼쪽 "마지막 수정 08.12 10:31 · 김준서"(회색 12px) · 오른쪽 버튼 "저장"(비활성: 배경 #F2F4F6, 글자 #C9CED6)

### 데스크톱 변경됨 (1050:12412)

- 변경된 카드(iOS) 헤더 상태 표시가 "저장하지 않은 변경 있음"(점 색 다름)으로 바뀐다.
- 카드 푸터에 "되돌리기"(회색 배경, 글자 #4E5968) + "저장"(주황 #E07A3A, 흰 글자) 두 버튼.
- 변경 안 된 카드(Android)는 기본 상태 그대로(앱에 반영 중 · 저장 비활성 · 되돌리기 없음).

### 데스크톱 앱 화면 미리보기 다이얼로그 (1050:12120)

- 전체 딤(#191F28 32%) + 가운데 다이얼로그(720px, 흰 배경, 둥근 20px, 패딩 24, 그림자)
- 헤더: "iOS 사용자가 보게 될 화면"(17px 굵게) · 오른쪽 "✕"
- 폰 목업 2개 가로 중앙 정렬(각 300×600, 둥근 28px, 배경 #FBFBFA + 딤 40%)
  - 왼쪽 라벨 "강제 업데이트 · 1.3.0 미만" → 목업 "앱 미리보기/force": 가운데 모달(260px, 둥근 20px) = 래디 일러스트(96px) · 제목 "Landit 새 버전 출시!" · 본문 = forceUpdateReason 입력값(예: 안정적인 이용을 위해 최신 버전으로 업데이트해 주세요) · 주황 버튼 "업데이트하러 가기"
  - 오른쪽 라벨 "업데이트 권유 · 1.3.0 ~ 1.4.1" → 목업 "앱 미리보기/soft": 하단 바텀시트(위 모서리 24px) = 래디 일러스트 · "Landit 새 버전 출시!" · 본문 = softUpdateReason 입력값(예: 새 기능이 추가됐어요. 업데이트하고 만나보세요) · 주황 버튼 "업데이트하러 가기" · 텍스트 버튼 "나중에 할래요"
- 하단 안내(회색 12px 가운데): "입력한 문구가 그대로 들어가요. 문구를 비우면 앱 기본 문구("새로운 기능을 사용하려면 업데이트가 꼭 필요해요" / "새로워진 기능을 만나보세요")가 나와요."
- 소프트 라벨의 상한(1.4.1)은 최신 버전(1.4.2) 바로 아래 버전으로, 범위 표기는 "최소 지원 ~ 최신 미만"을 뜻한다.

### 모바일 (1050:12047 · 1050:12588 · 1050:12325)

- 상단바(52px): 햄버거 메뉴 · 오른쪽 점 + "개발 서버"
- 타이틀: "앱 버전"(26px 굵게) + "저장하면 앱에 바로 반영돼요"(14px 회색)
- 세그먼트 탭(연회색 트랙, 선택 탭 흰 배경): "iOS" · "Android" — 한 번에 한 플랫폼만 보여준다
- 그룹 3개(강제 업데이트 · 업데이트 권유 (소프트) · 기록)를 세로 스택. 데스크톱과 같은 필드 구성. 미리보기 링크 텍스트는 "미리보기"로 짧아짐.
- 하단 고정 CTA(흰 배경, 위 그림자, 패딩 20/12/30, content 하단 여백 110px)
  - 기본: "저장" 전체 폭 비활성
  - 변경됨: "되돌리기"(회색, 고정 폭) + "저장"(주황, flex 1)
- 모바일 미리보기(1050:12325): 딤 위 하단 시트(위 모서리 24px). 헤더 "강제 업데이트 · 1.3.0 미만이 보는 화면" · "✕" · 폰 목업 1개(270×540, force 모달). 소프트 미리보기는 별도 프레임 없음(같은 시트에 soft 목업이 들어가는 것으로 추정, 확인 필요).

## 판정 규칙 — 앱이 언제 뭘 띄우나 (BE가 판정, 앱은 updateType만 따름)

| 앱 버전이…                                            | updateType | 앱에서 보이는 것                                                                                                                     |
| ----------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 최소 지원 버전(minimumSupportedVersionName) 보다 낮음 | FORCE      | 강제 업데이트 모달 — 닫을 수 없음, 스토어로만. 문구 = forceUpdateReason                                                              |
| 최소 지원 ≤ 앱 버전 < 최신(versionName)               | SOFT       | 소프트 업데이트 시트 — 닫을 수 있음. 문구 = softUpdateReason. 닫으면 그 실행 동안은 다시 안 뜨고, 앱을 다시 켜면 다시 뜸(저장 안 함) |
| 최신과 같거나 높음                                    | NONE       | 아무것도 없음                                                                                                                        |

| 변경됨 (화면 프레임) | 카드 헤더 "저장하지 않은 변경 있음" + 되돌리기·저장(주황) 노출                                   |

## 검증

스펙 그룹명은 "필드 검증".

| 필드                                 | 검증                 | 비고                                                              |
| ------------------------------------ | -------------------- | ----------------------------------------------------------------- |
| versionName                          | x.y.z (semver)       | 최소 지원보다 낮으면 오류 "최신 버전이 최소 지원 버전보다 낮아요" |
| buildNumber                          | 양의 정수            | Android는 versionCode                                             |
| minimumSupportedVersionName          | semver ≤ versionName | 올리면 그 아래 사용자는 강제 모달 → 저장 확인 문구로 강조         |
| forceUpdateReason / softUpdateReason | 1~80자               | 앱 모달/시트에 그대로 노출(LAN-185 문구 톤)                       |
| releaseNote                          | 선택, 500자          | 줄바꿈 유지                                                       |
| releasedAt                           | 날짜시간             | 미래도 허용(예약 배포 표기용). 판정엔 안 쓰임                     |

## BE 확인 사항 / 열린 질문

스펙에 BE 확인 그룹은 없고, "미리보기 (있으면 좋음)" 그룹이 있다.

### 미리보기 (있으면 좋음)

- 카드 옆에 "이 정책이면 앱 1.3.5 사용자는 → 소프트 시트" 식의 시뮬레이터 입력 한 칸. 지금 시안엔 없음, 2차

### 스펙 텍스트와 화면 프레임 사이 차이(참고)

- 검증표는 forceUpdateReason / softUpdateReason을 "1~80자"(필수)로 두지만, 미리보기 다이얼로그 하단 안내는 "문구를 비우면 앱 기본 문구가 나와요"라고 되어 있어 빈 값을 허용하는 것처럼 읽힌다. 필수 여부 확정 필요.
- 미리보기 다이얼로그의 앱 기본 문구("새로운 기능을 사용하려면 업데이트가 꼭 필요해요" / "새로워진 기능을 만나보세요")가 실제 앱(사용자 웹 features/app-update)의 기본 문구와 같은지 확인 필요.
- 카드 푸터의 "마지막 수정 08.12 10:31 · 김준서"에서 수정자 이름을 표시하는데, GET admin/app-versions 응답 필드 목록에는 updatedAt/updatedBy가 없다. 마지막 수정 시각·수정자를 어디서 받는지 확인 필요.
- 모바일 미리보기 프레임(1050:12325)에는 강제 업데이트 시트만 있고 소프트 미리보기 시트는 없다. 소프트도 같은 형태의 시트로 가정.
- 저장 확인 AlertDialog의 전체 카피(제목·버튼)는 스펙에 영향 문장만 있고 나머지는 없다.
