# Git Commit

커밋 메시지 형식: `{type}: 커밋 메시지`

- **scope 없음** — landit-admin은 앱이 하나다. `feat(web):` 같은 scope를 붙이지 않는다.
- **제목**: 한국어 서술형 한 문장 — "~한다", "~~로 정리한다", "~~를 뺀다" (landit-fe 로그와 같은 톤). 명사 나열("~~ 추가", "~~ 수정")보다 문장이 우선.
- **본문**: "왜"를 산문으로. 무엇을 했는지는 diff가 말하니 본문은 이유·배경·트레이드오프·이 변경이 남기는 영향을 쓴다.
- 커밋 1개 30줄 이내 권장. 한 문장으로 설명이 안 되면 쪼갠다.

## 타입 목록

| Tag      | 설명                                                               |
| -------- | ------------------------------------------------------------------ |
| feat     | 새로운 기능 추가                                                   |
| fix      | 버그 수정                                                          |
| design   | 사용자에게 보이는 UI 시각적 변경 (레이아웃, 색상, 컴포넌트 디자인) |
| style    | 코드 포맷 변경, 세미콜론 누락 등 동작에 영향 없는 코드 정리        |
| refactor | 동작은 그대로, 코드 구조/가독성 개선                               |
| type     | 타입 정의 수정                                                     |
| docs     | 문서 수정                                                          |
| comment  | 주석 추가 및 변경                                                  |
| chore    | 빌드, 패키지 매니저, 환경 설정 등 개발 환경 관련                   |
| lint     | ESLint 설정 수정 및 린트 에러 수정                                 |
| deploy   | 빌드 및 배포 작업                                                  |
| test     | 테스트 코드 추가 및 수정                                           |
| rename   | 파일 또는 폴더명 변경                                              |
| remove   | 파일 삭제만 한 경우                                                |
| security | 보안 헤더·인증·프록시·의존성 취약점 등 보안 관련 변경              |

## 애매한 경우 판단 방법

타입 선택이 불확실하면 변경 내용을 설명하고 사용자에게 확인 후 커밋.

## 메시지 작성 기준

- 좋음: `fix: 일괄 답장 확인창의 선택 건수가 0으로 보이던 것을 고친다`
- 나쁨: `fix: 버그 수정`
- 좋음: `security: 프록시의 변경 요청에 same-origin 검사를 더한다`
- 나쁨: `security: 보안 강화`

본문 예시.

```
fix: 세션 시작 응답의 진행도를 제출 응답과 다른 타입으로 나눈다

백엔드가 두 응답에 이름만 같은 다른 레코드를 쓴다 — 시작 응답에는
currentMessageSequenceNumber가 없다. 한 타입으로 쓰면 없는 필드를 있다고
선언하게 되고, 테스트도 단언으로 그 구멍을 덮게 된다.
```

## 예시

```
feat: 피드백 목록의 유형·상태 필터를 쿼리스트링에 둔다
design: 사이드바 서버 카드 간격을 Figma 셸 스펙에 맞춘다
docs: 공지·업데이트 스펙에 발행 취소 흐름을 적는다
chore: 스웨거에서 API 타입을 생성하는 스크립트를 둔다
remove: 대시보드의 임시 안내 문구를 뺀다
!HOTFIX: 프로덕션에서 로그아웃 후 쿠키가 남는 문제를 고친다
```
